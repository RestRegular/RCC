## 1. 总体语法风格（已确认）

- 内存模型新增语法尽量遵循 Rio 现有关键字、类型声明、函数声明和表达式风格，不另起一套语法体系。
- 类型统一用方括号：`Ref[T]` / `Mut[T]` / `Take[T]` / `Body[T]` / `Content[T]` / `Link[T][peer][cardinality]`。
- 关键字、子句、标签均小写。

## 2. 出生地（已确认）

### 2.1 语法位置

- 出生地写在 `var` 声明的标签区，与类型标签用空格分隔。
- 标签区顺序不敏感：类型与出生地标签可任意顺序出现。
- 出生地标签只适用于 `Body` 和 `Content`，普通变量不需要。

```rio
var n: int = 10
var p: Body[Player] pool = Player()
var c: Content[Player] pool = bob.take()
```

### 2.2 取值与默认

- 出生地标签只有两类：
    - **省略** = 默认当前作用域局部池。
    - **Pool 类型变量名** = 指定该 Pool 为出生地。
- **删除 `local` 关键字**：标签区写了 = 指定非默认 Pool；不写 = 当前作用域。不再有 `local` 这种显式同义写法。
- **删除 `outer` 关键字**：不引入“跳一层”语法。要活到外层，就显式登记进外层 Pool。
- 标签区最多一个出生地标签（一个 Pool 名），其余是类型。
- 出生地标签必须是一个 Pool 类型的变量名。

### 2.3 类型标签可省

- 类型标注可省，走现有推导。
- 出生地标签可省，默认当前最内层块。
- 两者都能省：`var c = bob.take()`。
- 允许只给出生地不给类型：`var c: pool = ...`，前提是类型可推导、`pool` 能解析成 Pool 变量。
- 消歧靠符号表：是 Pool 类型变量即出生地，否则当类型名。
- **不加**“Body/Content 必须显式写类型”的可读性约束。

### 2.4 “当前作用域”的精确定义

- 默认出生地 = 声明所在的**最内层块**作用域。
- 对象存活范围严格对齐词法作用域：块内声明只能块内用，出块即销毁。
- 要用到块外，必须显式登记进外层 Pool。
- 与 §8.8“循环体每轮一个”、§2.2“绑定所在作用域”一致，不引入“向上提升”推断。

## 3. Pool 与出生地（已确认）

### 3.1 Pool 自身有出生地

- Pool 是普通 Rio 对象，**自身有出生地，走统一规则**，不搞特殊资源。
- `var pool: Pool = Pool.fixed(100)` 默认出生在当前块；要活到外层就显式登记进外层 Pool。

### 3.2 两层角色分开

- **作为容器**：托管对象先做安全检查、逐个销毁，再销毁 Pool 壳子。
- **作为被管理对象**：按自己的出生地正常销毁。
- 两个角色可在同一个 Pool 上同时存在，但销毁时机不同。

### 3.3 生命周期约束

- **R1**：以 Pool P 为出生地的对象，存活范围不得超出 P 的存活范围。
- **R2a**：Pool 的出生地关系成树，**无环**，静态检查。
- **R2b**：销毁链从叶子到根；`child` 出生在 `parent` 时，parent 销毁前须验证 child 已可销毁/已销毁。
- 兄弟关系合法：`x` 出生在 `parent`、`child` 也出生在 `parent`，x 与 child 是兄弟。

### 3.4 通用 Pool

- Pool 不带类型参数。
- 同一个 Pool 可管理不同类型对象；Body 和 Content 都可使用同一个 Pool。
- 对象静态类型由编译器分别追踪；Pool 负责统一分配与生命周期管理。
- 第一版保留三种分配策略：`fixed` / `boxed` / `chunked`，都属于通用 Pool。
- Pool 是 Rio 标准库普通类型；Body / Content / Ref / Mut / Take 是特殊语义类型；编译器负责静态安全检查；core ABI 负责底层内存操作。
- 不把 Pool 做成内置关键字，不把分配策略写死在编译器。

## 4. 类型名与 Body / Content（已确认）

- `Player` 与 `Body[Player]` 是**同一个类型**，`Player` 是简写，编译器内部统一成 `Body[Player]`。
- **不编码状态**：`Player` 不隐含 Full；状态仍由事实表 + 窄化管理。
- `Content` 必须显式写 `Content[Player]`；`Player` 不表示 Content。
- `var c: Player = b.take()` 是编译错误（Body vs Content 类型不匹配）。
- **“用类型名编码状态”记为后续议题**，不进 P13-1。

## 5. `ctor` 与构造（已确认）

### 5.1 `ctor` 降级为普通函数名

- `ctor` 是**保留名**，专用于构造函数；用户不能定义同名普通方法。
- 解析走“省略 `fun` 的函数定义”，不是关键字特判。
- **定义处必须省略 `fun`**：`ctor(...) { ... }` 合法；`fun ctor(...) { ... }` **编译报错**。
- 构造函数重载走 §4.5 普通重载规则。
- `super(v)` 语义不变，机制上等价于调父类 `ctor` 重载集。

### 5.2 两种构造语义

- `Player("b")` ≡ `Body(Player.ctor("b"))`：调构造函数 + 隐式封装成 Body，结果 `Body[Player]`。
- `Player.ctor("b")`：只执行构造函数体，不封装，结果 `Content[Player]`。
- 两者决议同一套重载集，只差封装。
- `Player.ctor(...)` 是成员访问，走普通成员访问语法。

### 5.3 `Body(x)` 显式构造

- `Body(x)` 是“给已有 Content x 造 Full 壳”的显式构造操作。
- **必须在有出生地的位置**：`var` 标签、`fill` 目标、`return result`；裸表达式出现在别处**编译报错**（Body 出生地永远显式，无匿名 local）。
- `Body(...)` ≡ “空壳 + fill(x)”。

## 6. `take` 语义（已确认）

### 6.1 基本语义

- `bob.take()`：内容**位置不动**，标记“本条语句内可转移”。
- 语句结束时：若被**落定**则 bob→E；否则**回填**，bob 仍 F。
- `bob.take()` 的表达式类型是 **`Content[Player]`**（不是 `Take`）。
- `var t = bob.take()` 合法，t 是 Content。

### 6.2 落定位置（四种）

1. `var c = bob.take()`
2. `fill(...)`
3. `return ...`
4. **实参位置且对应形参类型为 `Content[T]`**

其余位置（实参但形参非 Content、运算、读字段）算“使用”，语句末回填。

### 6.3 隐式 take

- 形参为 `Content[T]` 时，传 Body 或 Content 自动 take，与显式 `bob.take()` 语义一致。
- **静默生效，无提示语法**。
- 显式 `take` 保留，用于非 `Content` 形参位置的显式触发或可读性。

### 6.4 独占与挂起

- 只要某实参位置（隐式或显式）take 了 x，其余实参中不得有指向 x 同一 slot 的 `Ref`/`Mut`，除非能证明 `≠`。
- 同一语句内对同一 body 第二次 take 报错（挂起期间独占）。
- **落定立即生效**；未落定 take 在语句末回填；多个未落定 take 各自回填，互不影响。
- **挂起期间独占**：同一 body 在挂起期间不能再次 `take` / `fill` / `clear` / `release`，报错。
- 挂起期间**允许**通过引用读、直接读写 `bob.hp`（位置没动，内容同一份）。
- **挂起态在事实表里单独表示**（F 的子状态或独立维度）。
- `bob.take()` 作为独立语句（既不落定也不使用）——**编译警告**，不阻断编译。
- `return bob.take()` 落定到 result，bob→E，返回值类型必须 `Content[T]`。
- 挂起期间**不允许**把 bob 传给 `Take[T]` 形参的调用（等于第二次 take）。

## 7. 引用与能力（已确认）

### 7.1 三种能力语法

- 类型统一方括号：`Ref[T]` / `Mut[T]` / `Take[T]`。
- 表达式：
    - `&bob` 或 `bob.ref()` → `Ref[Player]`
    - `bob.mut()` → `Mut[Player]`
    - `bob.take()` → `Content[Player]`（见 §6）
- **Body 默认有 `ref()` / `mut()` / `take()` 三个方法**，三种能力语法对称。
- 不给 `Mut` 造 `&mut` 前缀。

### 7.2 `&` 的规则

- `&` 作**前缀** = 取引用；作**中缀** = 位与，按位置区分。无解引用运算符。
- `&Player` ≡ `Ref[Player]`，**同一类型**，`&Player` 是简写。
- `&bob` ≡ `bob.ref()`，只能对 Body 变量取引用；对 Content / 字面量 / 表达式报错。
- **`&` 优先级低于字段访问**：`&p.name` = `&(p.name)`，是精确路径子引用。
- `(&p).name` 合法，语义是“通过壳子引用访问字段”，路径登记保守（`⊤`）。括号不是风格，是表达不同意图。

### 7.3 `Mut` 与 `Take` 的等次

- `Mut` 是一等引用（可绑定、可存）。
- `Take` 是二等值（只在实参/落定位置出现）。
- `Take[T]` 只作为**函数形参类型**出现；无产出的表达式、无可持有的变量。
- 调用点只写 `f(bob)`，由形参类型决定语义：`Take[T]` → 独占取内容；`Mut[T]`/`Ref[T]` → 对应能力；`Content[T]` → 隐式 take 落定。
- **不引入 `take bob` 调用语法**。
- `var x: Take[T]` / `-> Take[T]` / 字段 `Take[T]` 均编译错误。

## 8. 子引用与局部排他（已确认）

- 子引用创建统一用 `&`：`&p.name`、`&p.team.captain`；`&p`（p 是 Body）是壳子引用。不引入 `name_ref()` 这类专门方法。
- 冲突检查用 **NLL**（活跃到最后使用），不是词法块末尾。
- 结构体字段存子引用按整个内容登记，用户语法不变，编译器内部保守处理。
- `List` 和 `Pool` 都有 `split`，方法名统一；不提供按谓词拆的 `split_if`。
- `xs.split(k)` 按下标拆成两段 `Mut` 视图，路径 `xs[0..k)` / `xs[k..)`，互不相交。
- `xs.get_mut(i)` 返回单元素 `Mut`，路径登记为 `xs[*]` + 运行时下标标记；与不同下标不冲突需证明 `i≠j`（不等事实）。
- 路径语法与 §4 对齐：静态部分精确，动态下标保守，靠不等事实放宽。

## 9. 签名标注（已确认）

### 9.1 三个子句

- `from[...]` / `writes[...]` / `ensures[...]`，各自独立书写。
- **关键字不可省略**：必须写 `from` / `writes` / `ensures`，不能只留方括号。
- **位置自由**：写在签名区（返回类型后、`{` 前）或函数体 `}` 后均可；子句之间顺序也不限制。
- **整体省略**：只有当没有任何子句时，整段不写；不允许空方括号 `[]` / `from[]` / `writes[]` / `ensures[]`。

### 9.2 `ensures`

- 标记：裸名 = Full，`+a` = 显式 Full，`?a` = 不确定，`!a` = Empty；未列出的 `Take` 形参默认 `?`。
- 只对 `Take[T]` 形参生效，列其他类型报错。
- **每条正常出口**（`ret`、走到末尾）都必须满足 `ensures`，任一出口不满足报错。
- **`throw` 出口不检查 `ensures`**；catch 之后 `Take` 形参状态回到 `?`，不沿用承诺。
- 验证逐出口，不是“存在某出口满足即可”。

### 9.3 `writes`

- 用户写的函数：缺省 `writes` 按函数体推断记（可实例级）。
- 接口 / 动态分发 / 外部接口：缺省记类型级 `(类型.字段)`。
- `writes[this.x]` 允许（方法内写自身字段）。
- `writes[a.x, a.y]` 多条目逗号分隔。

### 9.4 `from`

- 缺省 `from`：返回引用可能指向任意引用参数的任意路径（全集，保守）。
- **硬性检查**：返回引用不得指向本函数 `local`（含 Body/Content 的 local、临时值），违反报错。
- `from[a.x, b.y]` 多来源逗号分隔，语义“可能来自其中之一”。
- 编译器验证函数体返回引用的来源 ⊆ `from` 声明。
- 缺省保守：不写 `from` 则返回引用默认指向整个参数内容；不写 `writes` 则记类型级效果；不写 `ensures` 则 `Take` 形参状态为 `?`。

## 10. `fill` / `clear` / `release`（已确认）

### 10.1 `fill(c)`

- 前置：目标确定 E（F 报错先 `clear`）。
- 后置：目标 F，c H→X。
- 冲突：与目标 body 的活跃**子引用**冲突；与壳子引用不冲突。
- 目标类型须匹配（`Content[T]` 填 `Body[T]`）。

### 10.2 `clear()`

- 前置：目标确定 F；已 E 时 **no-op 幂等**。
- 后置：目标 E，旧内容销毁。
- 冲突：与活跃子引用冲突；壳子引用不冲突。

### 10.3 `release(x)`

- 前置：§6.4 判据——所有活跃集合中 x 重数为 0、无活跃壳子/子引用、状态已 E、含 Link 则 Link 空且不在任何 Link 中。
- 后置：槽位回收，可复用。
- 冲突：与**任何活跃引用**冲突（壳子引用、子引用都不行）。

## 11. Content 赋值即移动（已确认）

- Content 变量赋值 = 移动（`var a = b` → b: X）。
- Content 实参传 `Content[T]` 形参 = 移动。
- Content 返回 = 移动（落定 result）。
- 拷贝用显式 `clone()`（深拷贝，P13-1 起）。
- 非 `Content[T]` 形参（`any` / `Ref` / 具体类型）**不移动** Content 变量；`sout(Content)` 是编译器特化，读内容不消耗，与 §3.5“Content 不能被引用”不冲突（读值，非建引用）。

## 12. 控制流与可返回值作用域（已确认）

### 12.1 可返回值作用域

- 裸块 `{ ... }`、`if`/`else` 分支、`for`/`while` 循环体、函数体、`catch`/`finally`（暂定“是”）。
- **裸块指块表达式**：块出现在右值位置（`var a: int = { ret 10 }`、实参、返回表达式）时
  才是可返回值作用域；作为独立语句的裸块按 §15.1 处理，不是。
- **循环体块不是独立可返回值作用域**：循环体内 `ret value` 直接退循环，等价 `break value`。

### 12.2 类型标注

- 带 condition 的结构（`if`/`while`/`for`）标返回类型时 **condition 必须加括号**：`if (cond): T { ... }`。
- 裸块不需要。
- 返回类型可省（推断）。
- **无类型标注的 `if`/`for`/`while` 默认 `void`**，不可作右值，`break`/`ret` 不带值、仅退出。
- 控制结构作右值：类型由 `: T` **或**出口值唯一推断；必须唯一、非 void；冲突/不可推断/void 报错。显式 `: T` 不是强制要求。
- `if` 作表达式：所有分支必须产生值；作语句：不要求。
- 带类型标注的循环自然结束时，表达式值为 **`T` 的类型零值**（`int` → 0）。
- `while` 与 `for` 同等支持 `break value`、作表达式、自然结束取零值。

### 12.3 发散出口

- **发散出口**（`return` / `throw`）**不参与**可返回值作用域的值类型检查；只有正常出口（`ret value`、`break value`、自然结束）必须产出标注类型。
- 所有出口都发散时，表达式类型为**发散类型**（可赋给任意类型，后续代码不可达）。
- 引入发散类型（never/`!` 语义），Rio 原无此概念。

## 13. 带值退出（已确认）

### 13.1 三关键字分工

| 关键字 | 退出什么 | 带值 |
|---|---|---|
| `ret` | **最近的可返回值作用域**（函数体 / 块表达式 / `if`/`for`/`while` 分支） | ✓ |
| `return` | **只退函数**，无视块边界 | ✓ |
| `break` | **只退最近循环**，可带值 | ✓ |

- `ret` 最通用，语义由所在作用域决定。
- **函数体顶层 `ret` 退函数**（因为函数体就是最近的可返回值作用域），与 `return` 行为一致，不是特例。
- `ret` 只退**最近一层**，不支持“退 N 层”或标签。
- `ret` 在 void 上下文不带值；`ret value` 在 void 上下文报错。
- `break` 退最近**循环**，跳过 `if`/裸块等非循环块；不能跨函数边界。
- 嵌套循环里 `break` 退最近循环。

### 13.2 类型匹配

- `ret value` 在标 `: T` 的块里，value 类型须匹配 T。
- `break value` 在标 `: T` 的循环里，value 类型须匹配 T。
- `return value` 类型匹配函数返回类型。
- 同一作用域里 `ret value` 与 `break value` 都参与类型合流。
- 嵌套时各自匹配所属作用域的标注类型。

## 14. 循环与不动点（已确认）

- 循环体内 `var` 默认出生地 = 循环体块，每轮新建、每轮销毁。
- 循环外变量在循环体内 take/fill，状态合流取格上界（循环后 `?`）。
- 子引用靠 NLL + 不动点，用户语法不变。
- 无专门循环出生地语法。

---

## 15. 块作用域与并发（已确认 / 推迟）

### 15.1 块作用域

- 不引入 `scope s` 作用域对象；`{ ... }` 块本身就是局部作用域，出生地默认对齐块。
- 裸 `{ ... }` 块可作为独立语句，是局部作用域。
- 裸块内 `var` 默认出生地 = 该裸块，块末销毁。
- `ret` / `break` / `continue` 在裸块内按外层上下文生效。
- **与 §12.1 的分工**：§12.1 的「裸块是可返回值作用域」指的是**块表达式**
  （块出现在右值位置，如 `var a: int = { ret 10 }`）；作为**独立语句**出现的
  裸块不是可返回值作用域，块内 `ret` 按外层上下文生效（即退函数 / 循环 / if）。
  两条并不冲突，区别只在块出现在值位置还是语句位置。

### 15.2 并发（整段推迟，不在 P13-1）

- `scope` / `spawn` / `par_each` / `Locked` / `Chan` / 并行组合检查**整段推迟**。
- §10 全部移出 P13-1 讨论范围。
- 闭包语法若将来用于并发，统一成 Rio 现有 `(p: T) -> { ... }`，不用 `|p|`。
