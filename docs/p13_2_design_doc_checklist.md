## 1. Pool 类型与出生地标签区（解锁 L1-12 + §3）

**为什么阻塞**：决议 §2.2「出生地标签必须是 Pool 类型变量」、§2.3「只给出生地不给类型时 pool 须能解析成 Pool 变量」。当前没有 Pool 类型，`var p: Body[Player] pool = ...` 里的 `pool` 无法解析，标签区判定顺序（内置→Pool→自定义→出生地）无法完整工作。

**需要设计/裁决的点**：
1. `Pool` 是标准库类还是编译器内建类型？（决议 §3.4 说"标准库普通类型、不做关键字"，但 `Pool.fixed(100)` 这类静态构造的语法落点未定）
2. `fixed` / `boxed` / `chunked` 三种分配策略的 API 签名与语义（决议 §3.4 只列了名字）。
3. Pool 作为"容器"与"被管理对象"的双角色，在 Rio 里用户怎么写？（`pool.add(x)` / `x` 的出生地标签反向登记？）
4. 出生地标签的 AST 表示：与类型标签同在 labelNodes 里，还是新增独立字段？（决议 Q-A 已定**判定顺序**，但未定 AST 落地形态）

## 2. fill / clear / release 的调用形态与状态语义（§10）

**为什么阻塞**：决议 §10.1 标题写 `fill(c)`，正文说"目标 E→F，c H→X"——但**目标如何绑定没写**。§5.3 说 `Body(x)` ≡ "空壳 + fill(x)"，暗示 fill 可能像构造式。没有明确签名就无法实现。

**需要设计/裁决的点**：
1. 调用形态：`p.fill(c)`（方法）/ `fill(p, c)`（全局函数）/ `fill(c)`（目标由上下文隐式绑定）？三选一或并存？
2. `clear()` / `release(x)` 的形态：方法还是函数？`release` 的 x 是槽位还是对象？
3. **E/F/H/X 四态的运行时表示**：当前 `_moveStates` 只有 bool（F/X 两态）。扩展为四态是编译期事实表，还是运行时元数据？后者的 ABI 变更需要用户批准。
4. 状态冲突检查：决议 §10 要求"与活跃子引用冲突、壳子引用不冲突"——依赖 #4 的子引用路径登记。

## 3. take 挂起态与独占检查（§6.4）

**为什么阻塞**：决议 §6.4 要求 `bob.take()` 后先标记 H（挂起），语句末根据是否落定决定 E 或回填 F；期间同一 body 二次 take/fill/clear/release 报错、允许通过引用读。当前实现是"take 本身不标记，只在落定位置标记"——**绕过了挂起态**，所以独占检查没做。

**需要设计/裁决的点**：
1. 挂起态是编译期事实表的一个维度，还是需要语句级事务（进入语句标记 H、语句末统一结算）？
2. "同一语句"的精确定义：分号分隔算一条还是多条？跨换行呢？
3. `bob.take()` 作为独立语句时决议要求"编译警告"——警告的具体形态与开关？
4. 未落定的 `take` 在异常路径（throw）下如何回填？这与 Q4 条件销毁相关。

## 4. 子引用 / NLL / 局部排他（§8）

**为什么阻塞**：这是全新基础设施，`&p.name` 的路径登记、活跃引用集合、冲突检查、不动点分析都需要从零实现。当前 `&` 前缀明确不支持子引用（L3 实测会报 L3 诊断）。

**需要设计/裁决的点**：
1. 路径的 AST/事实表表示：`p.name`、`p.team.captain`、`xs[i]`、`s[0..k)` 如何统一编码？
2. NLL 数据流分析的实现边界：过程内够不够？跨函数调用怎么保守处理？
3. `split_at(k)` / `split_from(k)` / `get_mut(i)` 的返回类型与路径登记时机；不等事实（i≠j）如何记录与消费？
4. 与 #2 的状态冲突检查如何共用事实表？
